# Dailogger iOS — 기술 스택 (v1.0 실제 사용 기준)

설계 단계에서 검토한 스택과 실제 출시 버전에 들어간 것을 정리했습니다.
카메라·영상 처리·온디바이스 AI가 핵심인 앱 특성상 크로스플랫폼(Flutter/RN) 대신
Apple 네이티브를 선택했고, 그 판단은 유효했습니다.

## 1. 실제 사용 스택 (요약)

| 영역 | 사용 | 비고 |
|---|---|---|
| 언어 | **Swift** (Swift 5 언어 모드) | 설계 때 검토한 Swift 6 strict concurrency는 미적용 |
| UI | **SwiftUI** + Observation(`@Observable`) | 단일 `AppModel`이 앱 상태 총괄 |
| 아키텍처 | 경량 MVVM — 뷰 + `@Observable` 모델 + 서비스 | SPM 멀티 모듈 대신 **단일 타깃 폴더 구조** |
| 영속성 | **SwiftData** (`@Model`, `@Query`, `FetchDescriptor`) | 서버·계정 없음, 완전 로컬 |
| 카메라 | **AVFoundation** — `AVCaptureSession` + `AVCaptureMovieFileOutput` 세그먼트 녹화 | 시뮬레이터는 목(타이머) 폴백 |
| 영상 처리 | `AVMutableComposition` 병합, `AVAssetExportSession`, `AVAssetImageGenerator` 썸네일 | |
| 재생 | `AVPlayerLayer`(뷰어 — 경량), AVKit `VideoPlayer`(릴 미리보기) | |
| 릴 오버레이 | **`AVVideoCompositionCoreAnimationTool`** + UIGraphicsImageRenderer로 그린 CALayer | 앱 디자인 그대로 영상에 합성 |
| AI 블로그 | **FoundationModels** (Apple Intelligence, iOS 26+, `#if canImport` 가드) | 미지원 기기는 캡션 기반 템플릿 폴백 |
| 위치 | **CoreLocation** + `CLGeocoder` 역지오코딩 | 원샷 요청, 장소명만 저장 |
| 위젯 | **WidgetKit** (systemSmall/Medium) + 앱 그룹 UserDefaults | `WidgetCenter` 리로드 |
| 알림 | **UserNotifications** 로컬 알림 (저녁 9시 리마인더) | 기록한 날은 자동 스킵 |
| 폰트 | String Catalog 아닌 **런타임 등록**(`CTFontManagerRegisterFontsForURL`) | 생성형 Info.plist 제약 우회 |
| 현지화 | **String Catalogs** (`Localizable.xcstrings`, ko/en) | `SWIFT_EMIT_LOC_STRINGS=NO`로 빌드 시 재작성 방지 |
| 프로젝트 | **Xcode 16 포맷** (objectVersion 70, 폴더 동기화 그룹) | 앱 + 위젯 2타깃 |
| 배포 | Xcode Archive → App Store Connect → TestFlight → 심사 | Fastlane 미사용 (규모상 불필요) |
| 최소 지원 | **iOS 17.0** | AI 기능만 iOS 26+ 조건부 |

## 2. 설계 대비 달라진 점과 이유

| 설계 | 실제 | 이유 |
|---|---|---|
| Swift 6 strict concurrency | Swift 5 모드 | AVFoundation 델리게이트·타이머 콜백 위주 코드에서 마이그레이션 비용 대비 이득이 작음 |
| SPM 멀티 모듈 | 단일 타깃 폴더 구조 | 화면 7개 규모에 모듈 경계 관리가 오버헤드 |
| iOS 18 최소 | iOS 17 최소 | 더 넓은 기기 지원, 사용 API가 17로 충분 |
| Swift Charts / App Intents | 미사용 | 2차 백로그 |
| 테스트 스위트·CI | 미구축 | 1인 개발 속도 우선, 실기기 수동 검증 |
| UserProfile 모델 | 삭제 | 로그인·프로필 자체를 제품에서 제거 |
| 무드(Mood) | UI에서 제거 | 캡션만으로 충분, 스키마에 흔적만 남음 |

## 3. 이 앱의 기술적 차별점

### 온디바이스 AI 블로그 (FoundationModels)
- 캡션·장소·시각을 입력으로 **기기 안에서** 일기 생성 — 서버 비용 0, 오프라인 동작,
  일기 데이터가 기기를 떠나지 않음 (심사 메모와 프라이버시 라벨의 근거)
- `@Generable`로 제목/본문 구조화 수신, 한국어 환경이면 한국어로 생성
- `#if canImport(FoundationModels)` + `@available(iOS 26, *)` 이중 가드로 구형 기기 안전

### 릴 영상 합성 (Core Animation Tool)
- 스토리 뷰어와 동일한 필·캡션 박스를 `UIGraphicsImageRenderer`로 그려
  `AVVideoCompositionCoreAnimationTool`로 영상 위에 합성 — 앱 안팎 룩이 일치
- 타임라인 스타일: 종이 배경 + 점선 레일 + 시각 도트 + 카드 안 영상 (키프레임 opacity로 세그먼트 전환)
- 소셜 안전 영역(상단 12%, 하단 25%) 준수 → 인스타 스토리에 올려도 UI에 안 가림

### 성능 패턴
- `NSCache` 썸네일 스토어 + 백그라운드 디코드(`preparingForDisplay`)
- 정적 DateFormatter 재사용, 텍스트 필드는 로컬 `@State` 후 저장 시 반영
- 진행 바 틱(10Hz)을 자식 뷰로 격리해 전체 리렌더 방지, 뷰어는 AVPlayer 1개 재사용
