# HaruLog iOS — 개발 명세 및 순서

## 1. 프로젝트 구조 (SPM 멀티 모듈)

```
HaruLog/
├── HaruLog.xcodeproj            # 앱 타깃 (조립만 담당)
├── App/
│   ├── HaruLogApp.swift         # @main, SwiftData 컨테이너 주입
│   └── RootTabView.swift        # 탭 셸 + 중앙 카메라 FAB + 오버레이 라우팅
├── Packages/
│   ├── DesignSystem/            # 색·폰트 토큰, HardCard, MoodPill, PrimaryButton, HLToast
│   ├── HaruLogCore/             # SwiftData 모델(Moment/DailyLog/UserProfile), Repository 프로토콜
│   ├── CameraKit/               # AVCaptureSession 래퍼, 세그먼트 녹화, 합본, 썸네일
│   ├── BlogAI/                  # FoundationModels 블로그 생성 + 템플릿 폴백
│   └── Features/
│       ├── TodayFeature/
│       ├── TimelineFeature/
│       ├── CalendarFeature/
│       ├── ProfileFeature/
│       ├── CaptureFeature/      # Camera + Edit
│       └── ViewerFeature/
└── Tests/                       # Swift Testing 단위 + 스냅샷 + XCUITest
```

- 의존 방향: `Features → (DesignSystem, HaruLogCore, CameraKit, BlogAI)`, 역방향 금지
- 각 Feature: `View` + `@Observable ViewModel` + (필요 시) `Router`

## 2. MVP 범위 정의

**포함**: 4개 탭, 카메라 세그먼트 녹화, 편집(캡션·무드·자동 위치/시각), 스토리 뷰어, 온디바이스 블로그 텍스트 생성, 로컬 저장(SwiftData), 스트릭 계산, 토스트/햅틱

**제외 (2차 이후)**: 소셜/공유, CloudKit 동기화, 위젯·App Intents, 블로그 릴 영상 자동 편집(음악·전환효과), 다크 모드, 원격 LLM 옵션, 알림(리마인더)

## 3. 개발 순서 (Phase별)

> 기간은 1인 개발 기준 러프 추정. 각 Phase 종료 시 시뮬레이터/실기기에서 데모 가능한 상태 유지.

### Phase 0 — 프로젝트 셋업 (0.5주)
- Xcode 26 프로젝트 + SPM 모듈 골격, Swift 6 strict concurrency 활성화
- SwiftLint/SwiftFormat, GitHub Actions(빌드+테스트) 연결
- 최소 타깃 iOS 18, 권한 문구(카메라·마이크·위치) Info.plist 정리
- **완료 기준**: CI에서 빈 앱 빌드 통과

### Phase 1 — 디자인 시스템 (0.5주)
- 색·폰트 토큰, HardCard/MoodPill/PrimaryButton/DurBadge/HLToast 구현
- 스냅샷 테스트로 컴포넌트 고정
- **완료 기준**: 컴포넌트 카탈로그 프리뷰 화면에서 와이어프레임과 대조 일치

### Phase 2 — 데이터 레이어 (0.5주)
- SwiftData 모델 3종 + Repository 구현, 시드(목) 데이터
- 스트릭·월간 기록일 계산 로직 + Swift Testing 단위 테스트
- **완료 기준**: 목 데이터 CRUD·파생값 테스트 그린

### Phase 3 — 탭 셸 + Today (1주)
- RootTabView(커스텀 탭바 + 중앙 FAB), Today 화면 전체
- 빈 상태(모먼트 0개) 처리
- **완료 기준**: 시드 데이터로 Today가 와이어프레임과 동일 렌더

### Phase 4 — Timeline / Calendar / Me (1주)
- 세 탭 화면 + Calendar 날짜 선택/월 전환, Me 통계·아카이브 그리드
- **완료 기준**: 4개 탭 전환·상호작용 완성

### Phase 5 — 카메라 (1.5주) ★ 기술 리스크 최상
- CameraKit: 세션 구성, 전·후면 전환, 세그먼트 녹화(시작/정지 반복), 타이머·세그먼트 바 UI
- 세그먼트 병합(AVMutableComposition) + 썸네일 추출, 위치 스냅샷(역지오코딩)
- 권한 거부 플로우
- **완료 기준**: 실기기에서 끊어찍기 → 단일 영상 파일 저장 확인

### Phase 6 — Edit + 저장 플로우 (1주)
- Edit 화면(캡션·무드·위치/시각), 저장 → Moment 생성 → Today 반영 → 토스트
- 키보드 회피, 뒤로 가기 시 초안 처리
- **완료 기준**: 촬영→편집→저장→목록 노출 E2E 동작

### Phase 7 — 스토리 뷰어 (1주)
- AVPlayer 기반 자동 진행, 진행 바, 좌/우 탭 이동, 길게 눌러 일시정지, Edit 진입
- **완료 기준**: 하루치 모먼트 연속 재생

### Phase 8 — 데일리 블로그 AI (1주)
- BlogAI: FoundationModels `@Generable`(제목/본문/해시태그) 생성, 미지원 기기 템플릿 폴백
- "Create daily blog" → 생성 → DailyLog 저장 → 블로그 화면(신규) 노출
- **완료 기준**: 실기기에서 온디바이스 생성, 폴백 경로 테스트

### Phase 9 — 폴리시 (1주)
- 햅틱, 전환 애니메이션, 접근성(VoiceOver·Dynamic Type), 한/영 로컬라이제이션
- 성능: 썸네일 캐시, 영상 파일 정리 정책
- **완료 기준**: 접근성 감사 통과, 메모리·저장공간 점검

### Phase 10 — 테스트·배포 (0.5주+)
- XCUITest 핵심 플로우(촬영→저장→뷰어→블로그), TestFlight 배포, 크래시 리포팅(선택: Sentry)
- App Store 심사 대비: 권한 사유, 개인정보 처리방침(온디바이스 처리 명시)
- **완료 기준**: TestFlight 외부 테스터 배포

**총 추정: 약 9~10주 (1인 기준)**

## 4. 리스크 및 대응

| 리스크 | 대응 |
|---|---|
| 세그먼트 녹화·병합 품질(끊김, 오디오 싱크) | Phase 5를 최우선 스파이크로 실기기 검증, 필요 시 `AVAssetWriter` 직접 제어로 전환 |
| Foundation Models 기기 제한(Apple Intelligence 지원 기기만) | 템플릿 폴백 기본 탑재, 기능 플래그로 분리 |
| 저장공간(영상 누적) | 해상도 1080p 제한, 오래된 원본 정리 옵션, 용량 표시 |
| 손글씨 폰트 한글 라이선스 | 무료 라이선스 폰트 우선 검토, 미확정 시 시스템 폰트로 출시 |
| 이 원격 환경(Linux)에서는 Xcode 빌드 불가 | 코드 스캐폴딩·리뷰는 여기서, 빌드·실기기 검증은 로컬 Mac에서 수행 |

## 5. 개발 컨벤션

- 브랜치: `main` ← `feature/phase{N}-{이름}` PR 머지, PR마다 CI 통과 필수
- 커밋: Conventional Commits (`feat:`, `fix:`, `refactor:` …)
- 테스트: Repository·계산 로직은 단위 테스트 필수, UI는 스냅샷 우선
- 문서: 각 Phase 완료 시 본 문서의 완료 기준 체크 갱신
