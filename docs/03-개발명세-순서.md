# Dailogger iOS — 개발 히스토리 및 현황

원래 이 문서는 Phase별 개발 계획서였습니다. v1.0 심사 제출까지 완료된 지금은
**실제로 진행된 개발 흐름의 기록**과 **남은 백로그**로 정리합니다.

## 1. 개발 흐름 (실제)

와이어프레임 → 웹 프로토타입 → 네이티브 앱 순서로 진행했고,
원격(Claude, Linux 환경)에서 코드 작성 → 로컬 Mac에서 pull 받아 빌드·실기기 검증하는
루프를 반복했습니다.

| 단계 | 내용 |
|---|---|
| 1. 와이어프레임 | Claude Design `하루로그-wireframe.dc.html` → 웹(HTML/CSS/JS) 프로토타입으로 구현 (저장소 루트) |

## 2. 설계 대비 주요 변경 (의사결정 기록)

| 결정 | 이유 |
|---|---|
| SPM 멀티 모듈 → 단일 타깃 | 화면 7개 규모에 모듈 관리가 오버헤드. 폴더 구조로 충분 |
| 로그인/계정 제거 | 서버가 필요한 기능이 없음. 완전 로컬 = 프라이버시가 곧 제품 정체성 |
| 무드·모먼트 제목 제거 | 캡션 하나로 충분, 입력 마찰 최소화 |
| 릴 자동 편집을 1차에 포함 | 당초 2차 계획이었으나 공유 가치가 커서 앞당김 (2종 스타일) |
| 위젯·리마인더를 1차에 포함 | 일기 앱의 리텐션 핵심이라 판단 |
| 테스트 스위트·CI 미구축 | 1인 개발 속도 우선, 실기기 수동 검증으로 대체 |

## 3. 원격 개발 워크플로

```
[Claude 원격 세션 (Linux)]                [사용자 Mac]
  코드 수정 → commit → push   ─────▶   git sync (checkout -- . && pull)
                                        → Xcode ⌘R 빌드
                                        → 실기기 테스트, 스크린샷 피드백
```

- Xcode가 pbxproj를 로컬에서 건드려 pull이 막히는 문제 → `git sync` 알리아스 +
  `SWIFT_EMIT_LOC_STRINGS=NO` + `.gitignore`(xcuserdata)로 해결
- 이 원격 환경에서는 Xcode 빌드가 불가하므로 **빌드 검증은 항상 Mac에서** 수행
